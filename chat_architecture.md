# Архитектура Двустороннего Чата (React + Supabase + Slack)

## Общая Концепция
Система представляет собой двусторонний чат в реальном времени, который позволяет клиентам на сайте общаться с операторами, работающими через корпоративный мессенджер Slack.
Вместо использования платных сторонних сервисов (таких как Intercom или JivoSite), реализована кастомная связка через открытую базу данных (Supabase) и бессерверные функции (Edge Functions).

## Основные Компоненты

1. **Frontend (React / Vite)**:
   - Компонент `ChatWidget.jsx`.
   - Отвечает за генерацию и хранение уникального `sessionId` клиента (в `localStorage`).
   - Поддерживает Real-Time подписку на базу данных для мгновенного получения ответов от оператора.
2. **База данных (Supabase PostgreSQL)**:
   - Таблица `chat_messages`, хранящая всю историю переписки.
   - Столбцы: `id`, `session_id`, `text`, `sender` (user/operator), `created_at`.
   - Включен механизм `Supabase Realtime` для публикации мгновенных изменений по WebSocket.
3. **Бэкенд (Supabase Edge Functions)**:
   - Функция `slack-webhook` (написана на Deno).
   - Выполняет роль моста между базой данных и Slack API.
   - Обрабатывает как исходящие запросы с фронтенда в Slack, так и входящие события (Events) из Slack на сайт.
4. **Slack App**:
   - Приложение с правами `chat:write` (писать) и `channels:history` / `groups:history` (читать треды).
   - Настроена подписка `Event Subscriptions`, которая "пингует" нашу Edge Function при новых ответах оператора.

## Как работают потоки данных (Data Flows)

### 1. Клиент пишет на сайте (Website -> Slack)
1. **Frontend**: Пользователь пишет сообщение. Приложение сохраняет его локально для мгновенного отображения в интерфейсе (Optimistic Update) и записывает в таблицу `chat_messages` в Supabase.
2. **Frontend**: Параллельно приложение вызывает облачную функцию `supabase.functions.invoke('slack-webhook')`, передавая `sessionId`, `text` и `threadTs` (ID треда в Slack, если он уже сохранен в `localStorage`).
3. **Edge Function**: Принимает запрос (`source: 'website'`) и вызывает API Slack `chat.postMessage`.
   - Если `thread_ts` **пустой** (это первое сообщение сессии) — функция создает **новое главное сообщение** в канале Slack и возвращает `ts` (ID этого треда) обратно на фронтенд. Фронтенд сохраняет его в `localStorage` (ключ `sunberg_chat_thread_...`).
   - Если `thread_ts` **передан** — функция отправляет сообщение как **комментарий в уже существующий тред** конкретного клиента.

### 2. Оператор отвечает в Slack (Slack -> Website)
1. **Slack**: Оператор нажимает `Reply in thread` под сообщением клиента и пишет ответ.
2. **Slack Event API**: Slack моментально отправляет Webhook (событие `event_callback`) на публичный URL нашей функции в Supabase.
3. **Edge Function**:
   - Проверяет, что это сообщение от человека (нет поля `bot_id`), и что оно находится внутри треда (есть `thread_ts`).
   - Вызывает Slack API `conversations.replies`, чтобы получить **самое первое (главное) сообщение** этого треда.
   - Из текста первого сообщения с помощью регулярного выражения извлекает ID сессии (формат: `Сессия session_x9f2k1`).
   - Делает `INSERT` нового сообщения в таблицу `chat_messages` со статусом `sender: 'operator'` и найденным `session_id`.
4. **Frontend**: Так как React-компонент подписан на обновления таблицы `chat_messages` через веб-сокеты (Supabase Channel), он мгновенно получает новое сообщение от оператора и отрисовывает его на экране без перезагрузки страницы.

## Безопасность и Ключи

- `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`: Публичные ключи для безопасного доступа к базе данных с фронтенда. Хранятся в `.env`.
- `SLACK_BOT_TOKEN`: Секретный токен (`xoxb-...`) для авторизации в API Slack. Зашит в защищенные `secrets` внутри облака Supabase.
- `SLACK_CHANNEL_ID`: ID канала Slack (например, `C0B4UK8CPHR`), куда бот отправляет сообщения. Также спрятан в `secrets` Supabase.

## Преимущества данной архитектуры
- **Изоляция диалогов**: Сообщения каждого клиента аккуратно складываются в свой собственный тред в Slack. Менеджер никогда не перепутает диалоги.
- **Сохранение контекста**: Так как история хранится в Supabase с привязкой к `localStorage`, если клиент обновит страницу или уйдет с сайта и вернется завтра, его переписка и ответы менеджера будут на месте.
- **Без сторонних серверов**: Не нужно оплачивать и поддерживать отдельный NodeJS-сервер.
- **Бесплатно**: В отличие от SaaS-решений, Supabase и Slack предоставляют щедрые бесплатные лимиты, которых достаточно для обработки тысяч чатов.
